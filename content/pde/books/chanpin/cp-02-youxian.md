## 考点梳理

### 2.1 优先级方法（**"3 种"**）

**RICE**（**"有数据时用"**）：

```text
RICE = (Reach × Impact × Confidence) / Effort
```

| 因子 | 定义 | 取值（示例） |
|------|------|-------------|
| **Reach** | 每季度触达用户数 | 如 5000 |
| **Impact** | 对单个用户影响 | **0.25 / 0.5 / 1 / 2 / 3**（微小/中/大/很大/巨大） |
| **Confidence** | 对以上估计的置信度 | **50% / 80% / 100%** |
| **Effort** | 人月 | 如 2 人月 |

**例题**：给远程团队做"会议待办自动生成"——Reach 5000/季、Impact 1、Confidence 80%、Effort 2 人月 → **RICE = 5000 × 1 × 0.8 / 2 = 2000**（分数越高越先做）。

**ICE**（**"没数据时快速排"**）：Impact / Confidence / Ease 各打 1~10 分，**加权求和**。

**Kano**（**"判断做了用户感不感知"**）：

| 类型 | 特征 | 例子（会议纪要产品） |
|------|------|---------------------|
| **基本型** | 没有就差评，有了不加分 | 转写准确率 |
| **期望型** | 做得越好越满意 | 转写速度 |
| **魅力型** | 没有不失望，有了惊喜 | 自动识别"谁负责哪条待办" |
| **无差异** | 做了没人感知 | 换了个图标颜色 |
| **反向** | 做了反而差评 | 强制登录才能用 |

> **记忆锚**：**"有数 RICE，无数 ICE，体验 Kano；砍'无差异'，保'基本'，抢'魅力'"**。

### 2.2 需求砍法（**"会砍才是 PDE"**）

**砍需求 4 问**（**"4 问"**）：

```text
① 这个需求对应哪个问题？   → 说不出 = 砍
② 不做会损失什么指标？     → 说不清 = 降优先级
③ Effort 能不能砍？        → 先做 80% 价值的 20% 工作量
④ 有没有更便宜的替代？      → 规则/模板/人工兜底
```

**"先做 MVP" 3 层**（**"3 层"**）：

| 层 | 内容 | 例子（会议纪要） |
|----|------|-----------------|
| **P0（不做就死）** | 核心任务能跑通 | 上传 → 转写 → 出待办 |
| **P1（做了大加分）** | 体验闭环 | 待办可编辑/导出/提醒 |
| **P2（锦上添花）** | 魅力功能 | 跨会议待办聚合 |

> **记忆锚**：**"P0 跑通，P1 闭环，P2 惊喜"**——**"MVP 是砍出来的，不是加出来的"**。

### 2.3 指标设计（**"3 层"**）

| 层 | 数量 | 定义 | 反例 |
|----|------|------|------|
| **北极星** | **只有 1 个** | 代表产品核心价值的结果指标 | "用户数 + 收入 + 留存"（3 个 = 没有） |
| **输入指标** | 若干 | 可被团队动作直接影响 | "活跃用户"（太结果，团队动不了） |
| **护栏指标** | 若干 | 不能变差的底线 | 转写准确率/投诉率 |

**设计步骤**（**"4 步"**）：

```text
① 定北极星：这个产品让用户"完成"什么？（结果导向）
② 拆输入：哪些动作能影响它？（可操作）
③ 设护栏：哪些指标变差就"赢了也输了"？
④ 埋点验证：数据真的能采到吗？
```

**示例**（智能会议纪要）：

- 北极星：**周完成"会议→待办"闭环的用户数**；
- 输入：录音上传数 / 待办生成数 / 待办采纳率 / 编辑后采用率；
- 护栏：转写准确率 ≥ 90% / 投诉率 < 1% / P95 时延 < 5 分钟。

> **记忆锚**：**"1 北多输入，护栏不能坏；数据采不到 = 指标白设"**。

## 🧠 记忆工具箱

### 口诀速记

- RICE：**"触达影响置信度，除以人月"**；
- ICE：**"三个十分加起来"**；
- Kano：**"基本期望魅力无差反向"**；
- 砍需求：**"说不清问题就砍，先做 80 价值 20 工作量"**；
- MVP：**"P0 跑通 P1 闭环 P2 惊喜"**；
- 指标：**"一北多输入，护栏不能坏"**。

### 场景锚点

- 优先级想象"**"行李箱装衣服"**"：你**不是"全部带走的人"**（**带不走**），**你是"挑衣服的人"**（**"取舍"**）——**"RICE 就是每件衣服的'值得带指数'（用多少/多重要/把握多大 ÷ 占多大地方）；MVP 就是'只装必穿的'（P0 跑通）；护栏就是'别把外套塞变形'（别为了装更多压坏底线）"**——**"装不下 = 砍，不是硬塞"**。

## ⚠️ 易错提醒

- **RICE"不写 Confidence = 伪量化"**：**"拍脑袋也要标 50/80/100%"**——**"不标 = 评审会追问"**；
- **Kano"魅力功能不是必做"**：**"先保基本，再抢魅力"**——**"基本型没做好，魅力型 = 白做"**；
- **北极星"3 个 = 0 个"**：**"团队会为不同北极星打架"**——**"只有 1 个"**；
- **指标"数据采不到 = 白设"**：**"先确认埋点能采到，再定指标"**（**"设了指标没有数据 = 自嗨"**）。
