> **用法**：认证/面试前只过这一页 + 作品集自查。**"能解释 > 能生成"**——**"AI 帮你写第一版，每个组件你都要能讲"**。

## 一、产品判断 4 问（**"问题定义"**）

```text
谁？        → 目标用户是谁（不是"所有人"）
什么场景？  → 在什么时机/环境下遇到
什么障碍？  → 现在的卡点是什么（现有方案差在哪）
什么结果？  → 做好了怎么衡量（指标）
```

> **"缺一不是好问题"**——**"给所有人做效率工具"= 没有定义问题**。

## 二、AI 状态 6 种（**"状态设计"**，最高频）

| 状态 | 设计要点 |
|------|---------|
| **加载中（流式）** | 逐字输出 + 可中断（停止按钮） |
| **等待（长任务）** | 进度/预期时间 + 可离开后回来 |
| **成功** | 结果可编辑/可复制/可再生成 |
| **失败** | 原因 + 重试 + 降级（换模型/简化任务） |
| **空** | 引导（示例提示词/模板） |
| **权限** | 额度不足/需登录/功能未开放 |

> **记忆锚**：**"流式能停，等待能走，失败能退，空能引"**——**只画成功页 = 评审直接减分**。

## 三、组件拆分 3 问（**"工程质量"**）

```text
① 能否复用？   → 不能拆出复用的部分 → 说明粒度错了
② 状态放哪？   → 局部用 useState，共享用 Context/状态库
③ Props 怎么定？ → 最小接口（别把整个对象传进去）
```

> **高频追问**："为什么这样拆？""哪里可能出错？""怎么优化性能？"——**"不能把答案推给模型"**。

## 四、AI 体验 5 要素（**"AI 产品设计"**）

| 要素 | 要点 |
|------|------|
| **透明** | 用户知道 AI 在做什么（状态/进度） |
| **可控** | 可中断/可编辑/可再生成/可回退 |
| **可信** | 引用来源/置信提示/不确定时明说 |
| **可恢复** | 失败可重试/降级/人工接管 |
| **可评估** | 有测试集/人工抽查/反馈入口 |

> **记忆锚**：**"透明可控可信可恢复可评估"**（**"5 个可"**）。

## 五、作品集三件套（**"主证明"**）

```text
① 设计过程：研究 → 问题 → 取舍 → 设计稿（有记录）
② 线上产品：真实可访问（不是录屏）
③ 代码仓库：GitHub + README（第二个人能跑）
```

**评审高频追问（提前准备）**：

- "问题怎么发现的？"（→ 研究记录）
- "为什么选这个方案？"（→ 取舍记录）
- "用户测试暴露了什么？你改了什么？"（→ 5 人测试 + 数据变化）
- "AI 输出错了怎么办？"（→ 失败/编辑/再生成）

## 六、数字卡（**"必背"**）

- **设计师参与度**：**41%**（Figma 2026，一年翻倍）；
- **开发者做设计**：**44% → 60%**（同报告）；
- **PDE 六步**：**找问题 → 画流程 → 做交互 → 写界面 → 推上线 → 看反馈**；
- **L1/L2/L3 学时**：**100~200 / 300~500 / 800+**（示例口径）。
