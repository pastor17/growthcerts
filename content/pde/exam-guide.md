> PDE 尚无统一官方考试——本节按行业通行做法整理**"测评 + 作品集评审"**的示例框架；**具体规则以各认证机构当次公告为准**。

## 时间线（示例口径）

| 环节 | 说明 |
|------|------|
| **报名** | 随时（在线注册，以认证机构为准） |
| **在线测评** | 产品判断 + 交互设计 + 前端基础（**60~90 分钟**，机考） |
| **作品提交** | 作品集三件套（**设计过程 + 线上产品 + 代码仓库**） |
| **项目评审** | 异步评审 + 可选视频讲解（**10~20 分钟**） |
| **结果** | 提交后 **2~4 周**（以机构为准） |
| **复审** | L2/L3 每年复审一次（**作品集更新**） |

## 测评形式（**"三层"**）

### 1 在线测评（**"理论 + 判断"**）

| 模块 | 题型 | 权重（示例） |
|------|------|-------------|
| **产品判断** | 单选/情境判断（问题定义/优先级/指标） | 30% |
| **交互设计** | 单选/设计评审（流程/状态/可用性） | 30% |
| **前端基础** | 单选/代码阅读（HTML/CSS/JS/React） | 25% |
| **AI 产品** | 单选/情境（大模型/提示词/Agent/RAG） | 15% |

合格线：**70 分**（100 分制，示例）。

### 2 作品集评审（**"主证明"**）

**三件套**（缺一不可）：

```text
① 设计过程：用户研究 → 问题定义 → 方案取舍 → 设计稿
② 线上产品：可访问的线上地址（真实数据/真实延迟）
③ 代码仓库：GitHub 仓库（生产级代码 + README）
```

**评审维度**（每项 1~5 分）：

| 维度 | 看什么 |
|------|--------|
| **问题质量** | 问题定义是否真实、是否做过用户验证 |
| **设计完成度** | 流程/状态/边界是否完整（**AI 状态是否覆盖**） |
| **工程质量** | 代码是否生产级（组件拆分/状态管理/错误处理） |
| **AI 体验** | 流式/等待/失败/引用/确认是否处理 |
| **可维护性** | README/注释/文档是否让"第二个人能接手" |

### 3 项目答辩（**L2/L3 可选**）

- **10~20 分钟**：讲"问题 → 方案 → 取舍 → 结果"（**不讲功能清单**）；
- 高频追问：**"为什么这样拆组件？""哪里可能出错？""AI 输出错了怎么办？"**

## L1~L3 门槛（示例口径）

| 级别 | 测评 | 作品集 | 项目数 |
|------|------|--------|--------|
| **L1** | ≥70 分 | 1 个响应式页面（表单/加载/成功/失败/空状态齐全） | 1 |
| **L2** | ≥80 分 | 1 个完整产品功能（问题→上线→数据）+ 答辩 | 1~2 |
| **L3** | ≥85 分 | 2 个完整功能 + 1 套组件系统 + 性能预算 | 2~3 |

## 备考路线（**"3~6 个月"**）

```text
① 基础轮（1~2 月）：HTML/CSS/JS + Git/PR + React/TS（前端主轴）
   或 用户研究/流程/原型/设计系统（设计主轴）
   ↓
② 项目轮（1~2 月）：完整做 1 个产品功能（问题→上线）
   ↓
③ 打磨轮（1 月）：找 5 个用户测试 → 修细节 → 整理作品集
   ↓
④ 认证轮（2~4 周）：在线测评 + 作品提交 +（L2/L3 答辩）
```

> **铁律**：**"AI 帮你写第一版，但每个组件都要能解释"**——面试/评审问到"为什么这样拆"，不能把答案推给模型。
