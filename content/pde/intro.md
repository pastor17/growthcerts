## 是什么

**PDE（Product Design Engineer，产品设计工程师）**是 AI 创业公司里"产品 + 设计 + 工程"三合一的岗位：

> **PDE 是能把产品问题想清楚、把交互设计出来、再亲手写成生产代码的人。**

传统流程是"产品经理写需求 → 设计师出稿 → 前端接稿开发"，三次交接、三次信息损耗。PDE 跨过这条交接链：**从用户问题一路做到可点击、可测试、可上线的产品体验**。

**PDE 一天在干什么**（以"智能会议纪要"为例）：

```text
找问题（1 小时会议还是 5 分钟语音？转写要等多久？）
  ↓
画流程（上传/处理/完成/失败，每步显示什么）
  ↓
做交互（Figma/代码可交互原型，真实用户试几遍）
  ↓
写界面（React/TS 生产代码，状态/响应式/无障碍）
  ↓
推上线（PR/过审/发布）
  ↓
看反馈（用户卡在哪？哪步错误最多？）→ 回到"找问题"
```

## 为什么 2026 年火了（三个结构性变化）

| 变化 | 说明 |
|------|------|
| **设计师第一次能直接碰生产代码** | AI 编程工具（Claude Code/Cursor/v0/Figma Make）把"学编程"的门槛打下来了；Figma 2026 已支持从画布直连代码库提 PR |
| **静态设计稿描述不了 AI 产品** | AI 产品有**流式输出/长时间等待/结果不确定/引用来源/人工确认/失败恢复**——只画"成功页"，工程团队不知道其他状态怎么工作 |
| **小团队要更短的交接链** | PDE 几天做出可用版本，少一次交接 = 少一次信息损耗 |

> **核心判断**：AI 让"能做"变便宜，**品味与完成度开始变贵**——上一阶段比谁能把页面做出来，这一阶段比**谁能把体验做完整**。

## 与产品设计师/前端的区别（**"看工作做到哪里"**）

| 对比项 | 产品设计师 | 前端工程师 | **PDE** |
|--------|-----------|-----------|---------|
| **问题定义** | 参与 | 不主导 | **主导** |
| **视觉/交互** | 主导 | 还原 | **主导** |
| **生产代码** | 不写/辅助 | 主导 | **主导（写进真实代码库）** |
| **上线维护** | 不 | 是 | **是** |
| **一句话** | 出稿 | 接稿 | **从问题到上线一条龙** |

**和产品设计师最大的差别**：要能进入**真实代码库**（组件/状态/接口/性能/无障碍），做完还愿意维护。
**和前端工程师最大的差别**：不等 Figma 稿——**自己判断流程、信息层级、交互与视觉**，并能解释为什么。

## L1~L3 能力分级（**"作品集 + 测评"**）

| 级别 | 名称 | 能力门槛（示例口径） | 典型岗位 |
|------|------|---------------------|---------|
| **L1** | **应用级** | 能用 AI 工具独立交付响应式页面（含表单/加载/成功/失败/空状态）；看懂组件、状态、接口报错 | AI 产品助理/设计开发 |
| **L2** | **设计级** | 能独立做用户研究并定义问题；能设计完整流程 + 状态系统；能写生产级 React/TS 代码并提 PR | Design Engineer（主岗） |
| **L3** | **架构级** | 能设计 AI 产品体验（流式/不确定/引用/确认/失败恢复）；能建组件系统 + 性能预算；能主导 0→1 产品功能 | 资深 Design Engineer/产品负责人 |

> **记忆锚**：**"L1 会用，L2 会判，L3 会定义"**——**每一级的"证"都是作品集**：设计过程 + 线上产品 + 代码仓库。

## 含金量与难度（AI 赛道决策参考）

| 维度 | 说明 |
|------|------|
| **岗位用途** | Design Engineer / PDE（**AI 创业公司/出海产品**） |
| **行业地位** | **作品集认证**（**"不是纸面资格"**）——**主证明是作品集**，纸面证书（软考/CAIP）是加分项 |
| **职称对应** | 软考中级/高级可对应 IT 职称（**"以考代评"**，与 PDE 并行） |
| **难度评级** | ★★★☆☆（**"产品 + 设计 + 工程"**，**"三合一"**） |
| **建议总学时** | **L1**：100~200 小时；**L2**：300~500 小时；**L3**：800+ 小时（含 2~3 个完整项目） |
| **主要难点** | **AI 产品状态设计**（流式/不确定/失败恢复）+ **生产级代码**（不是 AI 生成的第一版） |
| **适合谁** | 设计师补工程/前端补设计/产品经理补原型/零基础选主轴 |
| **建议先别学的情形** | 想"三天速成"（**PDE 很少是职业第一站**，更像设计与工程在某个项目里汇合） |

## AI 赛道证书地图（纸面证书 + 作品集双轨）

| 证书 | 类型 | 与 PDE 的关系 |
|------|------|--------------|
| **软考中级**（[系统集成](/ruanjian-kaoshi/)） | 以考代评职称 | **硬职称**（聘任/落户），与作品集并行 |
| **软考高级**（[高项](/ruankao-gaoxiang/)/[架构师](/ruankao-arch/)） | IT 高级职称 | L3 阶段的"天花板纸" |
| **CAIP/人工智能训练师** | 人社部新职业方向 | "AI 应用/训练"方向（以当地公告为准） |
| **1+X 数字创意/人工智能** | 职业技能等级 | "AI 应用"方向（以评价机构为准） |
| **PDE 作品集认证（本页）** | 作品集 + 测评 | **主证明**（设计过程 + 线上产品 + 代码仓库） |

> ⚠️ **关于数据的说明**：PDE 能力分级与证书地图为**示例口径**——**AI 赛道认证体系仍在快速成型**，以各认证机构与当地政策当次发布为准。
