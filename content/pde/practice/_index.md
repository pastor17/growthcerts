> **用法**：PDE 的"题"不是背答案，而是**训练判断**——做完看答案与错因，再问自己"我当初会怎么选？为什么？"
>
> **目标**：**"能解释 > 能生成"**——每个决策都能讲出"为什么"。

## 题 1：产品判断（问题定义）

**情境**：老板说"我们的 AI 产品用户留存低，你优化一下"。你的第一步是？

**选项**：
- A. 直接加推送/红点提升回访
- B. 先定义"留存低"（哪类用户？哪个环节流失？现有方案差在哪？）
- C. 竞品抄：把竞品功能全加上
- D. 让 AI 生成 10 个增长方案挑最好的

**答案**：**B**

**错因分析**：
- A 错：**"没诊断就开药"**——留存低可能是"新用户第一次没用成"（激活问题），推送只会骚扰；
- C 错：**"竞品功能 ≠ 你的问题"**（**"抄功能不抄问题定义"**）；
- D 错：**"AI 生成的 10 个方案没有一个是基于你的用户"**（**"生成 ≠ 定义"**）。

> **核心**：**PDE 的第一问永远是"问题定义 4 问"（谁/场景/障碍/结果）**——**"留存低"不是问题，"哪类用户在哪个环节为什么流失"才是**。

## 题 2：状态设计（AI 状态）

**情境**：你做 AI 会议纪要，转写要 3 分钟。"处理中"页面你**必须**设计什么？

**选项**：
- A. 转圈动画 + "处理中..."
- B. 进度说明（"正在转写→正在提取待办"）+ 预期时间 + 可离开后回来（任务持久化）
- C. 倒计时 + 背景音乐
- D. 让用户反复刷新查看

**答案**：**B**

**错因分析**：
- A 错：**"3 分钟转圈 = 用户以为死了"**（**"等待状态没有信息"**）；
- C 错：**"背景音乐与任务无关"**（**"装饰 ≠ 信息"**）；
- D 错：**"让用户刷新 = 把不确定性甩给用户"**（**"任务必须服务端持久化"**）。

> **核心**：**AI 等待状态三件套：进度（在干嘛）+ 预期（还要多久）+ 可离开（走了还能回来）**——**"流式能停，等待能走"**。

## 题 3：状态设计（AI 失败）

**情境**：AI 生成待办时模型超时了。错误提示**不应该**是？

**选项**：
- A. "处理失败，请稍后重试"（无原因）
- B. "转写超时：会议太长（> 2 小时）。建议：分段上传，或点击'用摘要模式重试'"
- C. 什么都不提示，界面卡在"处理中"
- D. "502 Bad Gateway"（原始报错）

**答案**：**A、C、D 都不合格；B 是正确答案**

**错因分析**：
- A 错：**"无原因 + 无降级"**（**"重试 3 次还超时怎么办？"**）；
- C 错：**"卡死 = 最差的失败体验"**（**"用户不知道发生了什么"**）；
- D 错：**"原始报错甩给用户"**（**"用户看不懂，也不该看懂"**）；
- **B 对**：**"原因（太长）+ 降级方案（分段/摘要）"**——**"失败 = 原因 + 重试 + 降级"三件套**。

## 题 4：组件工程（拆分）

**情境**：你的 `ChatPage.tsx` 已经 1800 行（输入框/消息列表/流式输出/重试按钮/用户设置全在一个组件）。评审问你"为什么这样拆"，**最差**的回答是？

**选项**：
- A. "AI 生成的，我觉得能跑就行"
- B. "先整体能跑，再按 UploadZone/TranscriptPanel/TodoList/ErrorBanner 拆，状态按 phase 枚举管理"
- C. "我参考了某个开源项目，它也是这么写的"
- D. "拆太细了不好维护，一个大组件好改"

**答案**：**A（最差）**

**错因分析**：
- **A 最差**：**"把答案推给模型 = PDE 一票否决"**（**"AI 帮你写第一版，每个组件你都要能解释"**）；
- C 错：**"抄结构不解释 = 没有判断"**（**"为什么它适合你？"**）；
- D 错：**"1800 行大组件 = 无法复用/无法单测/无法换局部"**——**"好改是错觉，改一处崩三处才是真"**；
- **B 对**：**"能讲拆分理由 + 状态管理策略"**（**"复用/状态/Props 三问"**）。

## 题 5：AI 体验（可信）

**情境**：你的产品用 AI 回答"公司报销政策"。用户问"差旅住宿标准"，模型**没检索到**相关政策。你应该？

**选项**：
- A. 让模型"根据一般经验"回答（大概率编一个）
- B. 明说"未找到相关政策，请查最新制度文档"，并给出文档链接
- C. 回答"按公司规定执行"（正确但无用）
- D. 把问题转人工

**答案**：**B**

**错因分析**：
- A 错：**"幻觉重灾区"**（**"报销标准编错了 = 用户真去报销被驳回"**）；
- C 错：**"正确废话"**（**"用户要的是答案，不是踢皮球"**）；
- D 错：**"人工是最后兜底，不是第一反应"**（**"成本 + 时效"**）；
- **B 对**：**"不确定时明说 + 给可信来源"**（**"可信 = 引用/来源/不确定时明说"**）。

## 题 6：组件工程（性能）

**情境**：你的 AI 聊天页流式输出时，用户输入框打字卡顿（INP 超标）。**最该先查**的是？

**选项**：
- A. 把字体换成更轻的
- B. 流式更新的渲染开销（每来一个 token 全列表重渲染？）+ 是否把大计算放主线程
- C. 加一个 loading 动画
- D. 把超时时间调长

**答案**：**B**

**错因分析**：
- A 错：**"字体不是 INP 主因"**（**"打字卡顿 = 交互响应慢"**）；
- C 错：**"动画掩盖问题"**（**"用户更卡了还更烦"**）；
- D 错：**"超时调长 = 问题还在"**；
- **B 对**：**"流式场景经典坑：每 token 触发全量重渲染 + 主线程做解析/计算"**——**"对策：消息虚拟化（只渲染可见）+ 批处理更新（攒几帧一起渲染）+ 重计算进 Worker"**。

## 题 7：AI 产品（选型）

**情境**：产品需求是"客服自动回复：FAQ 类问题用知识库回答，复杂问题转人工"。**最合适的技术选型**是？

**选项**：
- A. 全交给 Agent 自由发挥
- B. 工作流：FAQ 检索（RAG）→ 命中则答 → 未命中/置信低则转人工
- C. 纯规则关键词匹配（不用模型）
- D. 让用户自己选"找机器人/找人工"

**答案**：**B**

**错因分析**：
- A 错：**"步骤固定的业务流用 Agent = 不稳 + 贵"**（**"Agent 适合开放任务"**）；
- C 错：**"纯关键词 = 答非所问率高"**（**"自然语言别用精确匹配"**）；
- D 错：**"把路由成本甩给用户"**（**"用户不知道自己的问题算复杂还是简单"**）；
- **B 对**：**"固定步骤 + 知识密集 = 工作流 + RAG + 置信阈值兜底"**——**"工作流可控，RAG 给知识，阈值守底线"**。

## 题 8：产品判断（优先级）

**情境**：你的 AI 产品同时收到 3 个需求：① 修复"导出错乱"（核心功能，2 人天）；② 新增"多语言"（市场要求，6 人月）；③ 优化"启动动画"（设计建议，1 人天）。**第一优先**是？

**选项**：
- A. ③（最快，先上线个东西）
- B. ①（核心功能坏了）
- C. ②（市场要求，战略级）
- D. 三个并行

**答案**：**B**

**错因分析**：
- A 错：**"启动动画是 Kano 无差异型"**（**"做了没人感知"**）——**"先做无差异 = 优先级颠倒"**；
- C 错：**"6 人月的战略功能排在核心功能修复之后"**（**"P0 没跑通，P2 别动"**）；
- D 错：**"资源有限，并行 = 全半吊子"**；
- **B 对**：**"P0（核心任务能跑通）> P1（市场）> P2（锦上添花）"**——**"用 RICE 算也是 ① 最高：Reach 全量 × Impact 3（核心坏）× 100% ÷ 2 人天"**。

## 题 9：AI 体验（可控）

**情境**：AI 生成的周报用户不满意。**不合格**的设计是？

**选项**：
- A. 只能"重新生成"（每次结果都不同，用户像抽卡）
- B. 结果可编辑 + 可"换一段重写"（局部重生成）+ 保留历史版本可回退
- C. 生成后锁定，不许改
- D. 让用户手动改完再提交（AI 只出初稿）

**答案**：**A、C 不合格（B 最佳，D 可用）**

**错因分析**：
- A 错：**"整体重生成 = 抽卡体验"**（**"用户改了 3 段，重生成全没了 = 挫败"**）；
- C 错：**"锁定 = 不可控"**（**"AI 输出必须可编辑"**）；
- **B 对**：**"可编辑 + 局部重生成 + 版本回退"**（**"可控 = 可中断/可编辑/可再生成/可回退"**）；
- D 可用但弱：**"只出初稿 = AI 价值打折"**（**"PDE 要设计'人机协作'，不是'人替代机'"**）。

## 题 10：组件工程（无障碍）

**情境**：你的 AI 流式输出有"停止"按钮（`<div onClick={stop}>`），键盘用户反馈"Tab 不到停止键"。**正确**的修法是？

**选项**：
- A. 告诉用户"用鼠标点"
- B. 换成 `<button>`（原生语义 + 可聚焦）+ 可见焦点样式
- C. 给 div 加 `tabIndex={99}`
- D. 把停止按钮改成纯文字链接

**答案**：**B**

**错因分析**：
- A 错：**"把障碍甩给用户 = 无障碍不及格"**；
- C 错：**"`tabIndex=99` = 焦点顺序灾难"**（**"跳过了所有正常元素"**）；
- D 错：**"文字链接仍是'可聚焦但语义弱'"**（**"且样式可能被用户样式覆盖"**）；
- **B 对**：**"语义（button）+ 焦点（原生可聚焦）+ 可见（:focus-visible）"**——**"无障碍 4 项：语义/焦点/对比/键盘"**。

## 题 11：AI 产品（评估）

**情境**：你改了一个提示词，想确认"没把原有功能改坏"。**最该做**的是？

**选项**：
- A. 自己手动试 3 个问题感觉还行就上线
- B. 跑一遍回归测试集（20~50 个真实任务 + 期望行为），对比改前改后
- C. 直接上线，看用户反馈
- D. 让另一个大模型评价新提示词

**答案**：**B**

**错因分析**：
- A 错：**"3 个问题是幸存者偏差"**（**"改坏的正好不在 3 个里"**）；
- C 错：**"拿用户当测试集 = 事故"**（**"AI 产品改动 = 必须回归"**）；
- D 错：**"模型评价模型 = 幻觉评幻觉"**（**"要有'期望行为'作 ground truth"**）；
- **B 对**：**"评估 4 步：测试集 → 自动跑 → 人工抽 → 用户反馈"**——**"没有测试集的 AI 产品，每次改动都在赌博"**。

## 题 12：产品判断（MVP）

**情境**：你要做"AI 费用记录"（拍照/语音 → 自动记账）。**P0（MVP）**应该是？

**选项**：
- A. 拍照 OCR + 语音 + 多账本 + 月度报告 + 分享
- B. 语音记账 → 自动生成"金额/类别/日期" → 用户确认/编辑 → 存入（跑通核心闭环）
- C. 先做一个记账的 UI 原型（不接 AI）
- D. 先把 OCR 准确率做到 99%

**答案**：**B**

**错因分析**：
- A 错：**"全量功能 = 不是 MVP"**（**"6 个月做不完，验证不了核心假设"**）；
- C 错：**"UI 原型验证不了'AI 记得准不准'"**（**"核心假设是 AI + 确认闭环"**）；
- D 错：**"准确率 99% 是护栏，不是起点"**（**"先跑通闭环，再提准确率；且'用户可编辑'能兜住 90%"**）；
- **B 对**：**"P0 = 核心任务跑通（记一笔能成功）"**——**"MVP 是砍出来的：先 1 个入口（语音）+ 1 个闭环（确认）+ 1 个兜底（可编辑）"**。
