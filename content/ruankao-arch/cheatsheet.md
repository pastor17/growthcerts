> **用法**：考前 3 天起只过这一页 + 错题笔记 + 论文素材卡。⚠️ 软考**三科须同一次考试内全部合格**。

## 一、五大架构风格（判别即可）

| 风格 | 代表 |
|------|------|
| **数据流** | 批处理、**管道过滤器** |
| **调用/返回** | 主程序—子程序、面向对象、**分层** |
| **独立构件** | 进程通信、**事件驱动（隐式调用）** |
| **虚拟机** | 解释器、规则系统 |
| **仓库** | 数据库、超文本、**黑板**（多知识源协同求解） |

**4+1 视图**：逻辑（功能与对象）、**进程（并发与通信）**、开发（模块组织）、物理（部署），外加场景视图串联。

## 二、质量属性与场景

**六属性**：性能、可用性、安全性、可修改性、可测试性、易用性。

**质量属性场景六要素**：**刺激源、刺激、制品、环境、响应、响应度量**。

**评估中的四个"点"**：

| 概念 | 含义 |
|------|------|
| **敏感点** | 实现**某一**质量属性需重点关注的决策 |
| **权衡点** | 影响**多个**质量属性、需要折中 |
| **风险点** | 可能导致问题的决策 |
| **非风险点** | 可接受的安全决策 |

**评估方法**：**ATAM**（多属性权衡）、**SAAM**（可修改性）、**CBAM**（成本效益）。

## 三、计算卡（必须手算）

| 考点 | 公式 |
|------|------|
| **系统可用性** | **MTBF /（MTBF + MTTR）** |
| **年停机换算** | 99.9% ≈ **8.76 小时**；99.99% ≈ **52.6 分钟**；99.999% ≈ **5.26 分钟** |
| **串联可靠度** | R = R₁ × R₂ |
| **并联可靠度** | R = 1 −（1−R₁）（1−R₂） |
| **性能指标** | 响应时间、吞吐量（TPS/QPS）、并发数、资源利用率 |

**算例**：MTBF=9900、MTTR=100 → **99%**；两个 0.9 并联 → **0.99**。

## 四、分布式与新技术

| 考点 | 要点 |
|------|------|
| **CAP** | 分区容忍（P）必选，**在一致性（C）与可用性（A）之间取舍**；BASE 为最终一致 |
| **API 网关** | 统一入口：路由、认证鉴权、限流熔断、协议转换、响应聚合 |
| **注册/配置中心** | 服务发现；配置集中管理与动态推送 |
| **消息队列** | 异步解耦、削峰填谷（一对多通知场景） |
| **微服务 vs SOA** | 服务粒度更细、独立部署；SOA 依赖 ESB |
| **云原生** | 容器、编排（K8s）、Serverless、可观测性 |
| **大数据** | Lambda/Kappa 架构、数据湖、流批一体 |
| **其他** | 边缘计算、区块链、AIGC 相关（以当年度大纲为准） |

## 五、论文（与高项同逻辑，更偏技术）

```
摘要约 300 字：项目背景 + 本人角色 + 架构方案 + 效果
正文：项目背景（规模/技术栈/我的职责）→ 架构方案与选型理由 → 关键难题与解决 → 效果数据 → 总结与不足
```

**常见主题**：高可用架构、高并发架构、架构评估、微服务/云原生、数据架构、安全架构、性能优化。

**素材卡要点**：用户量/日请求量/数据量、技术选型对比、架构图要素（分层、缓存、消息、存储）、**可量化效果**（响应时间、可用性、成本）。

## 六、案例与综合的答题抓手

| 设问 | 答法 |
|------|------|
| 选型对比 | 用**质量属性**建维度（性能/可用性/可修改性/成本/风险）逐项对比后给结论与理由 |
| 质量属性分析 | 写**场景六要素** + 对应策略（如可用性：冗余、心跳、故障转移） |
| 性能问题 | 定位瓶颈（CPU/IO/网络/锁/数据库）→ 给方案（缓存、异步、读写分离、分库分表、池化） |
| 架构评估 | 用 ATAM 思路：敏感点 → 权衡点 → 风险点 → 非风险点 |

## 七、时间分配

```
综合知识：客观题 ≤1 分钟/题
案例分析：每题 15~20 分钟；先写结论与理由，再补细节
论文：审题 5 分钟 → 列纲 5 分钟 → 成文 60~70 分钟 → 检查 10 分钟（务必写完）
```

> 考前 3 天只看：**本页 + 公式卡（可用性/可靠度）+ 论文素材卡 + 易错提醒**。
