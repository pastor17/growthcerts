## 一、本证该记什么（三类笔记）

### ① 对比表笔记（架构师的核心武器）

| 对比组 | 只记判别要点 |
|--------|------------|
| **五大架构风格** | 数据流（批处理、**管道过滤器**）、调用返回（主程序子程序、面向对象、分层）、独立构件（进程通信、**事件驱动**）、虚拟机（解释器、规则系统）、仓库（数据库、超文本、**黑板**） |
| **质量属性** | 性能、可用性、安全性、可修改性、可测试性、易用性——各记 1 个**典型策略**（如可用性：心跳/冗余/故障转移） |
| **评估方法** | **ATAM**（多属性权衡，产出敏感点/权衡点/风险点）、**SAAM**（可修改性）、**CBAM**（成本效益） |
| **分布式方案** | 微服务 vs SOA、**API 网关**职责、注册中心/配置中心、消息队列（异步解耦、削峰） |
| **一致性模型** | **CAP**（分区发生时在 C 与 A 间取舍）、BASE、最终一致 |

### ② 公式与计算卡（必考）

| 考点 | 公式/要点 |
|------|----------|
| **系统可用性** | **MTBF /（MTBF + MTTR）** |
| **年停机时间换算** | 99.9% ≈ 8.76 小时/年；99.99% ≈ 52.6 分钟/年；99.999% ≈ 5.26 分钟/年 |
| **串并联可靠度** | 串联 **R = R₁×R₂**；并联 **R = 1 −（1−R₁）（1−R₂）** |
| **性能指标** | 响应时间、吞吐量（TPS/QPS）、并发数、资源利用率 |
| **架构评估场景六要素** | 刺激源、刺激、制品、环境、响应、响应度量 |

### ③ 论文素材包（与高项同理但更偏技术）

准备 **2~3 个真实系统**（建议：一个高并发或大数据量系统、一个高可用系统），写清：业务背景与规模（用户量/日请求量/数据量）、技术选型与理由、架构方案（分层/微服务/缓存/消息/存储）、遇到的**具体技术难题与解决过程**、可量化的效果（响应时间下降、可用性提升、成本下降）。

> 论文主题常见方向：高可用架构、高并发架构、架构评估、微服务/云原生、数据架构（数据湖/数仓）、安全架构、性能优化。

## 二、避坑清单（架构师专属 9 条）

| # | 坑 | 正确做法 |
|---|----|---------|
| 1 | 把架构师当"项目管理"来考 | 本科目重**技术深度**（架构风格、质量属性、分布式与新技术），与高项的"管理广度"路线不同，**二选一别混淆** |
| 2 | 只背概念不会做案例 | 案例题要求"用质量属性场景分析""给出架构决策与理由"，需**动手写方案** |
| 3 | 论文没有真实系统素材 | 提前锁定 2 个自己做过的系统，把数据与指标写实；没有项目经验就别急着考 |
| 4 | 忽略"新技术"章节 | 云原生、容器与编排、Serverless、大数据架构、边缘计算、AIGC 相关已在考纲中体现，**用当年度大纲核对** |
| 5 | 可用性/可靠性计算不练 | MTBF/MTTR、串并联可靠度是**稳定计算考点**，必须手算到熟练 |
| 6 | 三科分年考 | 软考需**同一次考试内全部科目合格** |
| 7 | 论文打字速度不练 | 机考环境下论文靠打字，**速度与结构同样重要**（提前手打 3 篇以上） |
| 8 | 用旧资料（大纲与教程会更新） | 以**当年度大纲与新版教程**为准（如软考部分资格大纲近年有修订） |
| 9 | 低估投入（★★★★★） | 建议预留 **300~500 小时**，在职 6~9 个月；与高项同期报考风险极大 |
